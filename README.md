# 🌱 Income Farm

활동 내역과 예상 수입을 **컬러 블록**으로 쌓아 보는 게임형 수입 대시보드 PWA.
스마트폰 홈 화면에 앱으로 설치해서 사용할 수 있습니다.

## 주요 기능

- **블록 쌓기** – 활동 내용 + 예상 수입을 입력하면 왼쪽 탑에 컬러 블록이 떨어지며 쌓입니다. 금액이 클수록 블록이 높아집니다.
- **스코어 보드** – 블록이 추가될 때마다 누적 예상 수입이 카운트업 애니메이션으로 올라갑니다.
- **3초 롱프레스 파괴** – 블록을 3초간 꾹 누르면 균열 → 폭발 애니메이션과 함께 파괴되고 수입이 차감됩니다. 토스트에서 **되돌리기** 가능.
- **탭하여 수정** – 블록을 짧게 탭하면 내용/금액/날짜/카테고리를 수정할 수 있습니다.
- **기간 필터** – 전체 / 오늘 / 이번 주 / 이번 달.
- **월 목표** – 목표 금액을 설정하면 진행 바가 채워지고, 달성 시 컨페티가 터집니다.
- **레벨 시스템** – 누적 수입에 따라 씨앗 → 새싹 → … → 전설의 농부까지 성장합니다.
- **인사이트** – 최근 7일 바 차트, 지난달 대비 증감, 카테고리 비율, 연속 활동 스트릭.
- **사운드 & 햅틱** – Web Audio로 합성한 효과음, 진동 피드백(지원 기기).
- **데이터 관리** – JSON 내보내기/가져오기, 요약 공유(Web Share), 샘플 데이터, 초기화.
- **PWA** – 오프라인 동작, 홈 화면 설치(📱 아이콘), 앱 바로가기("활동 추가").

## 실행

정적 파일만으로 동작합니다. 아무 정적 서버로 열면 됩니다.

```bash
npx serve .
# 또는
python -m http.server 8080
```

GitHub Pages: 저장소 Settings → Pages → Branch `main` / root.

## 앱으로 설치

- **Android (Chrome)** – 상단 📱 아이콘 → 설치 프롬프트, 또는 메뉴 ⋮ → "앱 설치".
- **iPhone (Safari)** – 공유 ⬆︎ → "홈 화면에 추가".
- **데스크톱** – 주소창의 설치 아이콘.

## 구조

```
index.html            앱 셸
css/style.css         디자인/애니메이션
js/app.js             상태, 렌더링, 애니메이션, PWA 설치 로직

manifest.webmanifest  PWA 매니페스트

```

## v2 개선 사항

- 데스크톱 격자와 모바일 한 줄 블록, 소프트/픽셀/스트라이프/젬 디자인, 개별 컬러 선택. 블록마다 랜덤 디자인과 컬러를 배정하고 새로고침·다른 기기에서도 유지합니다.
- 활동·메모 검색, 카테고리·입금 상태 필터, 날짜·금액 정렬, 블록 크기 선택.
- 입금 완료/대기 관리, 이번 달 수확과 다음 레벨 진행률.
- CSV 내보내기, 안전한 JSON 가져오기(취소 시 변경 없음), 키보드 편집, 모션 줄이기.
- Supabase 이메일 코드 로그인, 계정별 오프라인 캐시, 기기 간 동기화와 동시 수정 충돌 감지.

**서버 설정 전에는 로컬 저장만 동작합니다.** 실제 클라우드 동기화는 아래 설정을 완료해야 활성화됩니다.

### 클라우드 배포 설정

1. Supabase 프로젝트의 SQL Editor에서 `supabase/schema.sql`을 실행합니다. `farms` 테이블은 사용자 본인의 데이터만 접근하도록 RLS가 설정됩니다.
2. Authentication의 Email 로그인을 활성화하고 **Confirm signup** 및 **Magic Link** 이메일 템플릿에 `{{ .Token }}` 인증 코드를 표시하도록 설정합니다. 실제 사용자에게 메일을 보내려면 사용자 지정 SMTP와 발송 제한도 확인합니다.
3. Vercel 프로젝트 환경 변수에 `SUPABASE_URL`(예: `https://프로젝트ID.supabase.co`)과 `SUPABASE_PUBLISHABLE_KEY`(`sb_publishable_`로 시작하는 공개 키)를 등록합니다. 비밀 키, service-role 키, 데이터베이스 비밀번호는 사용하지 않습니다.
4. Vercel의 프레임워크를 Other, 루트 디렉터리를 저장소 루트로 지정하고 재배포합니다. 별도 빌드 명령은 필요하지 않습니다. 정적 파일과 `api/config.js` 함수가 함께 배포되어야 합니다. `/api/config`에서 `configured: true`가 반환되는지 확인합니다.
5. 웹과 다른 디바이스의 설치 앱에서 **같은 이메일**로 로그인합니다. 저장 직후, 화면 복귀, 네트워크 재연결 및 활성 화면에서 15초마다 동기화됩니다.

참고: [Supabase 이메일 OTP](https://supabase.com/docs/guides/auth/auth-email-passwordless), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security).

### 기존 데이터와 충돌 처리

- 기존 `incomefarm:v1` 기록은 보존합니다. 로그인 후 **이 기기의 기존 기록 합치기**를 선택하면 현재 계정에 복사합니다. 같은 ID의 서버 기록은 유지하며 로컬 원본도 남습니다.
- 계정 기록은 게스트 기록과 분리됩니다. 로그아웃하면 게스트 기록이 표시되고, 미동기화 계정 기록은 다음 로그인을 위해 이 브라우저에 보관됩니다.
- 오프라인 수정은 연결 시 업로드합니다. 계정의 서버 기록을 아직 불러오지 못했다면 편집을 잠가 덮어쓰기를 방지합니다.
- 서로 다른 블록의 동시 수정은 병합합니다. 같은 블록 또는 목표를 동시에 다르게 수정하면 자동 덮어쓰기를 중단합니다. 서버는 revision을 비교하는 원자적 CAS 저장을 사용합니다.
- 충돌 해결 버튼은 현재 기록을 JSON으로 다운로드한 뒤 서버 기록을 불러옵니다. JSON 가져오기는 같은 ID를 덮어쓰지 않으므로, 충돌 백업에서 필요한 값을 확인해 해당 블록을 직접 수정하세요.
- API와 계정 데이터는 서비스 워커 캐시에 저장하지 않습니다. 공용 디바이스에서는 동기화 완료 후 사이트 데이터를 지우세요.

### 개발 및 검증

Node.js 22 이상과 Microsoft Edge를 사용합니다.

```sh
npm ci
npm run dev
npm run check
npm test
npm run test:browser
```

개발 서버는 `http://127.0.0.1:4173`입니다. Edge가 없는 환경은 `playwright.config.js`에서 `channel: 'msedge'`를 제거하고 `npx playwright install chromium`을 실행하세요.

자동 테스트는 데이터 검증·병합, 모바일/데스크톱 UI, 편집·CSV·가져오기 취소, 분리된 두 브라우저의 동기화, 오프라인 병합, CAS 재시도, 충돌, 로그아웃 격리를 검증합니다. 클라우드 테스트는 모의 API를 사용하므로 운영 환경에서는 실제 이메일 인증과 RLS를 별도로 확인해야 합니다. 서로 다른 계정으로 로그인해 다른 사용자의 기록을 조회/수정할 수 없는지, 동일 계정의 두 기기에 추가·수정·삭제·목표가 반영되는지 검증하세요.
